# Bitmap Icon Source Contract

Use this contract for every small icon, badge, marker, crest, emblem, or other style-sensitive compact visual asset.

## Core Rule

Do not replace approved-design icons with programmatically drawn vector-like shapes.

For style-sensitive UI, small icons must come from an approved bitmap source path:

- cut from the approved full-screen design
- cut from an approved generated asset sheet
- supplied by the user/project as a bitmap
- reused from an existing FairyGUI package bitmap
- generated by the image model with declared visual references, then reviewed and sliced

The following are forbidden for production icons unless the user explicitly requests a vector UI style and approves the exact result:

- FairyGUI Graph primitives
- SVG generation
- font glyphs used as icon substitutes
- PIL/ImageDraw procedural polygons, circles, lines, or rounded rectangles
- Canvas/Path2D procedural icon drawing
- code-generated placeholder icons renamed as production assets

Rasterizing a procedurally drawn vector shape to PNG does not make it an acceptable bitmap source.

## Required Manifest Provenance

Every `asset_manifest.json.assets[]` entry classified as an icon must contain `assetSource`:

```json
{
  "name": "icon_example",
  "type": "icon",
  "file": "fgui_xml/package/art/icon_example.png",
  "assetSource": {
    "mode": "approved_design_slice",
    "sourceFile": "generated/design/screen_design_final.png",
    "crop": [120, 80, 48, 48],
    "cleanup": "transparent_background_and_edge_repair",
    "reviewStatus": "approved"
  }
}
```

Allowed `assetSource.mode` values:

- `approved_design_slice`
- `approved_sheet_slice`
- `provided_bitmap`
- `existing_package_bitmap`
- `image_generation_with_reference`

For `image_generation_with_reference`, also require:

```json
{
  "referenceFiles": ["references/ui_style.png"],
  "evidenceFile": "reports/imagegen_asset_prompts.md",
  "reviewStatus": "approved"
}
```

Forbidden source modes include:

- `procedural_vector`
- `procedural_raster`
- `svg`
- `font_glyph`
- `graph`
- `shape_primitive`

## Icon Classification

An asset is treated as an icon when any of the following applies:

- `asset.type == "icon"`
- `asset.fgui.layer == "icon"`
- its registered semantic visual part declares an icon role
- its production name follows the project icon naming convention

The project may classify badges, crests, markers, emblems, and decorative miniatures as icon-like assets when their style depends on the approved design.

## Visual Part Rules

A required visual part whose role is an icon, badge, marker, crest, or emblem must use:

- `asset_image`
- `runtime_loader`
- `child_component` whose visible icon is asset-backed

It must not use `graph` as a production substitute.

Simple Graph remains allowed for genuinely geometric behavior such as:

- progress fill
- plain separator line
- temporary hit area
- translucent state overlay
- debug rectangle

Graph is not allowed for a sword, shield, heart, shard, flag, check mark, leaf, badge, crest, boot, star, currency symbol, or other art-directed icon.

## Script Audit

The validator scans project production scripts. If a declared icon asset name appears in a script that also uses procedural drawing operations such as:

```text
ImageDraw
draw.polygon
draw.ellipse
draw.line
draw.arc
draw.rectangle
draw.rounded_rectangle
svgwrite
Path2D
```

production is blocked until the icon is replaced by an approved bitmap source.

Post-processing scripts may crop, trim, resize, alpha-clean, or copy an approved bitmap. They must not redraw the icon shape.

## Hard Errors

```text
icon_asset_source_missing
icon_asset_source_mode_forbidden
icon_asset_source_mode_invalid
icon_slice_source_missing
icon_slice_crop_invalid
icon_generation_reference_missing
procedural_icon_generator_detected
icon_visual_part_graph_forbidden
icon_file_format_forbidden
```

## Review Gate

Before XML generation, visually compare each icon against the approved design or approved sheet:

- silhouette matches
- line weight and texture match
- palette and material match
- no generic vector-icon appearance
- transparent edges are clean
- icon is readable at actual FairyGUI display size
